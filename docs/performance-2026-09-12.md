- 头像请求：7,951,972 字节的 PNG → 10,538 字节的 WebP（本次桌面 DPR 1.5 选择 288 像素版本）。
- 21 张原始图片合计 32.31 MB；它们的默认预览合计约 0.75 MB。共生成 67 个响应式版本，原图仍用于图库放大查看。
- JavaScript 原来是单个约 533 KB 文件；优化后主入口约 427 KB，另有约 64 KB 的共享块和约 1 KB 的运行时。**首页初始 JS 合计约 491 KB**，不能只拿主入口冒充总加载量。Life/Gadgets 的页面代码按需加载。

- 本次页面初始采样的 CLS：首页 0.019 → 0.000；图库和工具页均为 0。字体、图片和轮播文字的占位得到稳定。

测量使用 Windows 上的 Chromium 内嵌浏览器、1280×720、DPR 1.5、中文与深色主题；本地生产构建，响应禁止缓存且未启用 gzip。资源数值含浏览器预取的下方图片，不等同于首屏可见图片总量；第三方未开放资源计时的字节不纳入。原始记录见 [测量数据](./performance-2026-09-12.json)。

这是本地实验，未进行手机真机、网络限速、长期内存采样或线上真实用户 INP 测量。单次 FCP/LCP 和长任务记录保留在 JSON 中，用于诊断，不作为线上速度提升比例或 Lighthouse 分数。

## 已落实的修改

1. **图片生成流程**：开发启动和生产构建会生成带内容指纹的 WebP、srcset 与宽高清单。按头像、论文、图库、文字预览选择不同尺寸；处理 EXIF 方向，避免放大原图，保留动画资源。禁用 JPEG 快速缩放，以免派生尺寸比例发生额外误差。
2. **图片加载**：头像优先加载；缩略图按实际显示尺寸选择资源；图库和相册卡片预留图片比例；灯箱点击后读取原始文件，异步解码。
3. **持续动画**：相册照片、背景与兴趣轮播只有在视口可见且页面可见时活动；减少动态效果偏好会停用连续动画。滚动卡片在该偏好下不缩放。
4. **渲染与滚动**：论文高度通过 ResizeObserver 直接更新 CSS 变量，避免整段 React 内容因高度变化重新渲染；图片预览的位置更新合并到一帧一次，去掉重复鼠标事件；工具卡片缓存边界，鼠标移动最多每帧写入一次变换。
5. **代码与请求**：使用 LazyMotion 和轻量 m 组件，仅加载所需动画能力；Life/Gadgets 分包；补充路由首次加载状态。统计脚本改为 load 事件触发，移除 100 ms 轮询；版本更新请求支持取消和缓存重新验证。
6. **导航兼容**：跨页返回首页章节时，等新页面完成渲染后再定位；已实测桌面时间线标题距顶部 20 px。手机页内定位为 72 px，避开吸顶导航。
7. **依赖维护**：在现有版本范围内修复依赖审计发现的 10 项问题，完整 npm audit 修复结果为 0；没有强制跨主版本升级。Vite 配置同步使用 import.meta.dirname。

## 验证

- npm run build：图片生成、7 张图库元数据校验、TypeScript 与生产打包通过。
- npm run lint、git diff --check：通过。
- 对 67 个 WebP 逐个读取实际尺寸：宽度与 srcset 描述符一致，比例误差在整数像素舍入范围内；21 张源图片均保留。
- 浏览器核对三个页面、图库按分类筛选、原图打开、Escape 关闭、文字中的图片预览、滚动相册恢复动画、语言与主题切换、跨页及页内锚点。
- 390×844 手机视口检查三个页面，英文与中文关键排版未发现横向溢出；英文切换后论文高度变量与实际高度一致。
- 最终页面未捕获 JavaScript 错误；首次懒加载路由的 HydrateFallback 警告已修复。GoatCounter 在 localhost 拒绝计数属于其正常行为。
